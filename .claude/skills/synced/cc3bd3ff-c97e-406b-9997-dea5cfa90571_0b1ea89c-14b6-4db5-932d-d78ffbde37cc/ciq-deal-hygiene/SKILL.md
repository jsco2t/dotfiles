# CIQ Deal Hygiene — rep self-serve (v4.6, report-driven)

Your hygiene analysis is **already done for you every morning** by RevOps and saved to **your Google Drive**. This skill **reads that report and walks you through applying the fixes** — it does **not** re-pull or re-score your book. (Re-deriving everything through the connector is what made earlier versions slow and gave different answers than your scorecard.) You review each deal, confirm the change, and your Claude writes it back to HubSpot.

**Core loop:** load your report → walk deal-by-deal → you approve a change → fresh-read that one deal → apply via the HubSpot connector → confirm. Call tools **only** to (a) write an approved change, (b) fetch a field/body the report didn't include, or (c) re-check a deal right before writing. **Never re-pull the whole book and never re-derive flags or scores** — the report is the source of truth and is exactly what you are scored on.

## What you need connected
- **Google Drive** (required) — your daily report is in your **"CIQ Hygiene Reports"** folder (one file per day, generated by RevOps and shared to you).
- **HubSpot** (required to apply fixes) — to write Next Step / MEDDPICC / contact labels / line items / close date back to your deals. A read-only HubSpot connector still works — you'll get drafted values to paste.

## Step 1 — Load your report (do NOT re-derive)
Your report is a **Google Doc** in your **CIQ Hygiene Reports** Drive folder, titled
`Hygiene Report — <Your Name> — <YYYY-MM-DD>`. You usually arrive via the **link in your Slack DM**;
otherwise open the **newest** Doc in that folder. Read it, then tell the rep the **report date + headline**
("Here's your hygiene report from <date> — score X/100; N deals need updates, M clean"). The Doc IS the
analysis (flags, recommended next step, MEDDPICC gaps + how-to-fix, evidence, resolver findings, HubSpot
links) — **do not re-pull or re-score.**
- **If today's Doc isn't there, say so and STOP.** Do not fall back to re-pulling/re-scoring the book.
  Tell the rep to ping RevOps.
- **Parse the Doc's trailing `MACHINE-READABLE DATA (JSON)` appendix FIRST** — it is the authoritative
  record of the book (contract: `references/report_schema.md`; wrapper: `schema` / `report_date` /
  `flags_as_of` / `headline` / `recommendations[]`). Every prose card is rendered FROM that JSON; take deal
  ids, flags, values, dates, and evidence from the JSON, and where prose and JSON differ, **the JSON wins**.
  A Doc published before the appendix existed (no such section) → read the prose cards as before.
- **Never fill context beyond the report.** Do not browse the rep's wider HubSpot book, other Drive files,
  Slack, or the web "for background" — the report already carries everything you are sanctioned to act on.
  The ONLY live reads in this skill are the Step-3 single-deal fresh-read and a specific field the report
  doesn't include (core loop, above).
- **Use the Doc's score-transparency sections (v4.6).** Each flagged deal carries **Score math** — the
  deal's own score, and per flag its points (CRITICAL 5 / WARNING 2, ×2 once ≥7d old), the reason it fired,
  and its **"clears when"** condition: treat that clear condition as the fix target for the deal. The
  headline carries the rep-level formula with the rep's actual numbers, and a **"Since the last report"**
  section shows what cleared / newly flagged / persists despite recent work — open the walk by reading
  that movement back to the rep (wins first).

The report **is** the analysis. Each deal carries: its flags, the recommended **next step** (dated), the **MEDDPICC fields to fill** + how to write each + any drafted text/evidence, the competitive **angle**, **resolver findings** (true-EC re-tag / reseller-about-end-customer contact / duplicate), and the HubSpot link. Clean deals are listed for a quick "still current?" check.

## Step 2 — Walk deal-by-deal (worst first — the report is already sorted)
Go in report order. For each deal present: the deal + link, its flags, and the proposed update(s). Get the rep's **explicit "yes"** before touching HubSpot.
- A **drafted value** (Next Step text, or a MEDDPICC field drawn from the deal's emails/calls) is shown as a **DRAFT to confirm or edit** — it is cited; never present it as settled fact.
- A **clarifying question** (a field the report flagged as having no evidence in the record) → **ask the rep** for the content; do not invent it.
- Don't skip silently: clean deals get a one-line "next step still current? (y/n)".

## Step 3 — Fresh-read, then apply (the safety gate)
**Right before writing to a deal, re-read THAT one deal live from HubSpot** to confirm current state (still open; fields as the report expected). This is the only routine live read — it catches anything changed since the morning snapshot and stops you acting on stale data. Then apply per `references/fix_playbook.md`:
- **APPEND** Next Step / MEDDPICC (never overwrite) · set Champion/EB **contact** labels (82/7) · fix line items · set `blockers` · **re-date `closedate` on an OPEN deal**. **Confirm each write with a re-read.** Do NOT write `hygiene_score`/`last_hygiene_score_date` — the batch owns both stamps and re-scores every deal at the next run (v4.6); tell the rep the score updates at the next morning's report, and the "Since the last report" section will confirm what cleared.
- Read-only HubSpot connector? Hand back the exact drafted value + where to paste it. Don't stall.

## Golden rules — these keep it trustworthy and SAFE (follow exactly)
1. **Principle 0 — cite or don't claim.** Every value traces to the report's cited evidence or the live deal. Never present an inference as fact; if you can't verify it, say so.
2. **APPEND, never overwrite.** Next Step and MEDDPICC fields are appended (read current → append → write back). Date-stamp Next Steps `M/D - <initials> - …`.
3. **Never fabricate.** A name, number, or date comes from the report's evidence, the deal's emails/calls, or the rep — otherwise **ask**. Never assert an event/conference/calendar date from training data.
4. **⛔ NEVER close, lose, win, reopen, or re-stage a deal — and NEVER touch a closed or Won deal (D-39, HARD SAFETY RULE).** Hygiene cleans the **open** book; it does not decide deal outcomes.
   - **Won/closed deals are out of scope, full stop.** The report contains only open deals. If a deal reads `hs_is_closed=true` OR is in a Won stage (`93217107` Sales Won / `1162796937` Alt Won — these report `hs_is_closed=false` but are terminal: PO received, awaiting finance booking) at fresh-read (Step 3), **drop it** and note "Won/closed — out of hygiene scope." Never analyze, flag, score, or write to a Won or closed deal.
   - **Never move a deal to a closed stage (Closed Lost/Won) or out of one (reopen)** — even on explicit request. Closing/losing/winning/reopening is a forecasting decision the rep makes **deliberately in the HubSpot UI** (where pipeline approval / closed-edit rules apply; the connector's API path **bypasses** them). If asked, **decline and direct the rep to do it in HubSpot.**
   - **A past close date is "re-date the OPEN deal," NEVER "overdue → close it lost."** You clean the forecast by working real deals and fixing data — never by writing deals off. If a deal is genuinely dead, say so and tell the rep to close it lost **themselves** in HubSpot.
   - **Stage advance** may be proposed but **executed only forward among OPEN stages**, on an explicit per-deal "yes" — never into or out of a closed stage, and never to/at/past Won.
5. **Champion / Economic Buyer empty = apply the contact LABEL** (Champion 82 / EB 7) for the contact the report identifies; ensure the contact is on the deal. Judge qualification on the MEDDPICC **text**, not whether the checkbox is filled.
6. **A future-dated customer cadence is on-cadence, not dark (DD-3).** If the report or the deal shows the customer asked to re-engage on a future date ("reach out in July"), it's **on hold until then** — surface the cadence, don't treat it as dark/stalled.
7. **Capture rep feedback — proactively.** At the **END of the run** ask: *"Did any flag, value, or recommendation look wrong? Tell me and I'll log it for RevOps."* Log EACH issue (don't batch) by **appending** a JSON item to that deal's `hygiene_feedback` property (read current → parse the array, or start `[]` → append → write back; never overwrite): `{ts, skill_version, feedback_type, check, skill_output, rep_correction, evidence, status:"new"}`. Honor a mid-run dispute or `/feedback <text>`; never argue or defend a flag.

## Sanctioned writes — the ONLY changes this skill may make (allowlist)
Append `hs_next_step`; append/fill the MEDDPICC text fields; set Champion/EB **contact** labels (82/7); fix **line items**; set `blockers`; **update `closedate` on an OPEN deal** to a realistic future date; append `hygiene_feedback`. (`hygiene_score` / `last_hygiene_score_date` are **batch-owned** — never write them; v4.6.) A forward **stage advance among OPEN stages** is allowed **only** on an explicit per-deal "yes." **Create a Meeting (or Call) engagement when a note documents a meeting that was never logged — the rep confirms the date / participants / outcome; associate it to the deal; NEVER fabricate (golden rule 1).** **Everything else is OUT OF SCOPE — above all, NEVER set a deal to Closed Lost / Closed Won, reopen a closed deal, or write to any deal where `hs_is_closed=true` OR where the deal is in a Won stage (`93217107` Sales Won / `1162796937` Alt Won — these report `hs_is_closed=false` but are terminal; golden rule 4).** If a rep asks for a close/lose/win/reopen, decline and tell them to do it in the HubSpot UI.

## What this skill does NOT do
- **Does not re-pull or re-score your book.** RevOps' daily engine does that; the Drive report is authoritative and is exactly what you're scored on. If the rep asks "how do I get to 100," explain the model from `references/run_record.md` — don't invent a number.
- **Does not write the `Hygiene Run` object** (the server batch owns scores/trend).
- **Does not handle company-association LABELS** (End-Customer 78 / Reseller 3 / Distributor 80) — the daily batch auto-tags those.
- **Sales pipeline only** — Renewal/Alt pipelines are out of scope.
